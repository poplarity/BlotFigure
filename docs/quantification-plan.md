## 1. 现状盘点（代码事实，非推测）

现有功能只有一个「灰度定量 CSV」（`js/wbui.js:1921` `exportQuant`），内核是 `js/wbengine.js:1671` `densitometry`。它已经能出数，但按发表要求衡量，是「能跑」而不是「可信」。

**它现在做的事**

| 环节 | 实现 | 位置 |
|---|---|---|
| 信号 | `chemiSignal`：亮图取原值，暗图取 `1 − 像素`，归一到 0–1 | `wbengine.js:172` |
| 积分区 | 纵向 = 条带 `b0−2 … b1+2`；横向 = 泳道中心 `±0.33 × pitch`（固定比例） | `wbengine.js:1675` |
| 背景 | 框内**非条带**像素的中位数，单一标量 | `wbengine.js:1682` |
| 体积 | `Σ max(0, 像素 − 背景)` | `wbengine.js:1684` |
| 饱和 | 任一像素 `≥ clip` 即 `saturated: true`（布尔） | `wbengine.js:1685` |
| 归一化 | 按**行名正则**认内参（`LOADING_RE`），同膜相除，再除以第 1 道 | `wbladders.js:164`、`wbui.js:1938` |
| 输出 | CSV：蛋白 / 膜 / 曝光 / 各道体积 + 比值行 | `wbui.js:1934` |

**已经具备、可直接复用的基础设施**（这是好消息，成本比想象低）

- `App.rowExpo(row)` 已对**每一行的每一张曝光**算过 `satFrac` / `snr` / `peak` / `bgMed` / `noise` / `factor`（`wbapp.js:1388`）。多曝光线性检验的数据现成。
- `rec.bits` 记录了位深（`wbapp.js:339`），能区分 16-bit TIFF 与 8-bit 导出。
- `App.processingLog()` 已是结构化 JSON（`wbapp.js:1955`），加定量参数是顺手的事。
- `WB.bandInBox` 有成熟的**纵向**条带剖面定位（`wbengine.js:1559`），横向剖面可照搬。
- **横向剖面其实已经有了**：`WB.detectBoxLanes`（`wbengine.js:1443`）里的列剖面 `prof[x]`（取每列最强 15% 的均值再开方压缩）+ 滑动开运算去背景（`1451-1465`），正是判定条带横向边界需要的东西。P0 的「积分宽度」不必从零写，是复用。
- 状态 `S` 里没占用 `quant` 字段，新增对旧项目向后兼容（老项目无此字段 → 用默认值）。

## 2. 发表级定量到底要求什么

只列能从文献确认、且与这个工具相关的：

**① 信号必须落在检测器线性范围内**
Butler 等（2019, *BioMed Res Int*, doi:10.1155/2019/5214821）用稀释系列证明：化学发光与红外荧光都会出现偏离正比、甚至饱和的情况；**当数据不正比于蛋白量时，用「目标/内参」相除做归一化本身就是错的**，会让归一化后的数据失去可比性。这是最关键的一条——它意味着归一化必须以「先确认线性」为前提。

**② 归一化方法会改变统计性质**
Degasperi 等（2014, *PLoS ONE*, doi:10.1371/journal.pone.0087293）比较三种策略：固定点（内参）、总和、最优对齐。结论：固定点归一化会**抬高 CV**，幅度取决于归一化点的选择；**应避免选低强度的归一化点**。总和与最优对齐则按均值重新分配误差。

**③ 内参选择本身有争议**
Sander 等（2019, *Anal Biochem*, doi:10.1016/j.ab.2019.03.010）与 Maloy 等（2022, doi:10.1016/j.ab.2022.114840）支持总蛋白（Ponceau / stain-free）优于管家蛋白。Rivero-Gutiérrez 等（2014, doi:10.1016/j.ab.2014.08.027）做了三者直接比较。Taylor & Posch（2014, doi:10.1155/2014/361590）给的是实验设计层面的要求。

**④ 必须能追溯**
期刊图像政策（工具已有 `README` 的 Image integrity 一节）要求线性调整、单行单图、饱和标记。定量还额外要求：参数、ROI、方法可复现。

**⑤ 统计不该由画图工具代劳**
n=3 的 t 检验是常见但脆弱做法。工具的正确边界是：给准数、给离散度、把归一化后的原始值交出去，而不是替用户下显著性结论。

## 3. 差距分析

| 要求 | 现状 | 判定 |
|---|---|---|
| 线性范围 | 无任何检验；只有布尔饱和标志 | **缺**（核心缺口） |
| 饱和区分 | 不区分「传感器饱和」与「8-bit 显示截断」 | **有偏** |
| 背景模型 | 单一标量中位数 + 每像素 clamp 0 → 正偏差 | **有偏** |
| 积分边界 | 横向固定 0.33·pitch，不看条带实际宽度 | **有偏** |
| 内参识别 | 靠行名正则；改名即失效；无法显式指定 | **脆弱** |
| 总蛋白归一化 | 不可能——`densitometry` 只接受 chemi 的 `cs` | **缺** |
| 归一化方法 | 只有「固定点 + 除以第 1 道」，不可选、不记录 | **受限** |
| 低强度归一化点警告 | 无 | **缺**（Degasperi 明确点名） |
| 重复结构 / 离散度 | 无 | **缺** |
| 参数入日志 | 无 | **缺** |

**一句话概括**：缺的不是「算体积」——那个已经有了；缺的是**线性范围验证**、**归一化的科学选择**、以及**可追溯性**。

## 4. 方案

### 4.1 数据模型（新增 `S.quant`，向后兼容）

```
S.quant = {
  method: 'control' | 'total' | 'sum' | 'none',
  controlRow: <row.id> | null,        // 显式指定，不再靠名字
  totalImage: <imageId> | null,       // Ponceau / stain-free 图
  lanes: { <col>: { role: 'sample'|'control'|'dilution', dilution: 1 } },
  linearity: { checked: bool, r2: number|null, mode: 'exposure'|'dilution' },
  background: 'lane-flank' | 'box-median',
  version: 1
}
```
老项目读不到此字段 → 用默认（沿用现有行为），不破坏 `.blotfig`。

### 4.2 算法改造（`densitometry` 重写为 `quantify`，旧的保留兼容）

1. **位深分级**
   - `bits ≥ 16` 且 `clip` 为真 → 「传感器饱和」
   - `bits ≤ 8` → 标记为「显示缩放，动态范围已在源头损失」，定量降级为**同膜内相对值**并强制在导出中声明
   - 这一点直接对应用户自己的 iBright 8-bit 情况，代码里已有先例注释（`wbengine.js:1640`）

2. **背景模型改为泳道侧翼**
   取该泳道左右各一条窄带（避开相邻泳道条带）的稳健中位数 + MAD，逐泳道独立；同时**去掉 `max(0, ·)` 截断**，改为对 `Σ(v − bg)` 直接积分并单独报告背景方差。截断会在弱带区系统性地抬高结果。

3. **横向积分宽度由剖面决定**
   复用 `detectBoxLanes` 的列剖面与开运算背景（`wbengine.js:1451-1465`），取峰两侧降到 35% 的位置作为积分边界，并设 `0.33·pitch` 作为上下限回退。这样窄带不掺背景、宽带不截断。

4. **饱和像素不参与积分**
   饱和像素是**下界**，不是测量值。排除后报告 `excludedFrac`；若 >2%，整道标记不可定量（沿用 `checks()` 已有的 0.002 阈值口径）。

5. **线性范围检验（本次方案的核心）**
   - **模式 A：多曝光自检**（无需用户操作，数据现成）
     同一行在多张曝光上的体积应正比于曝光因子 `factor`。回归 `volume ~ factor`（过原点），报告 R² 与偏离度。**必须说清楚：这只验证检测器线性，不验证信号正比于蛋白量。**
   - **模式 B：稀释系列**（用户声明）
     若用户在泳道上标了已知稀释倍数，回归 `volume ~ dilution`。这才是 Butler 意义上的检验。
   - 检验不通过 → `checks()` 出 **block 级**警告，禁止出「归一化比值」，只允许导出原始体积。

6. **归一化可选且强制记录**
   - `control`：显式指定的内参行（同膜）
   - `total`：Ponceau / stain-free 图按泳道积分（需让 `quantify` 接受任意图像，非 chemi）
   - `sum`：按 Degasperi 的总和法
   - 若归一化点强度低于该膜中位数的某个比例 → 警告（Degasperi 的结论）

### 4.3 重复与统计（范围要克制）

- 复用现有 `S.groups`（泳道区间 + 文字）作为**条件**，区间内的泳道作为**重复**。
- 输出：每条件 `n`、`mean`、`SD`、`CV`。
- **不内置 p 值**。理由：n=3 下的检验选择、多重比较、是否配对都依赖实验设计，工具无权替用户决定。改为导出归一化后的逐道数值（CSV + JSON），让用户在 R/GraphPad 里做。
- 跨膜合并默认**拒绝**：`checks()` 已有「图片分组不能证明同一张物理膜」的警告，定量沿用同一立场。

### 4.4 输出

- `blot_quantification.csv`：逐道 `volume, background, bg_noise, snr, integration_width_px, excluded_frac, bit_depth, exposure, factor`
- `blot_quantification.json`：同上 + 方法、参数、线性检验结果、软件版本
- `App.processingLog()` 增 `quant` 段
- **自动生成方法段落**（英文，可直接进 Methods）：软件与版本、积分方式、背景模型、归一化方法、线性检验结果、n。这是审稿人会要的东西。

### 4.5 UI

最小侵入，不新增步骤（五步流程是既定产品边界，见 AGENTS.md）：

- `Export ▾` 里现有「灰度定量 CSV」升级为**「定量分析…」**，打开一个小面板
- 面板内：归一化方式下拉、内参行选择、线性检验按钮与结果、条件/重复预览、导出
- 所有新字符串走 `L('中文','English')`，导出内容一律英文

## 6. 验证策略

**合成真值（可自动化，进 CI）**
`WBDemo` 能生成已知参数的合成膜。据此构造：
- 已知振幅比的条带 → 检验 `quantify` 还原比例误差 < 某阈值
- 已知饱和的条带 → 检验被正确排除并标记
- 已知线性 / 已知饱和的两组多曝光 → 检验线性检验模式的判别力（真阳性 + 假阳性）
- 8-bit 与 16-bit 同图 → 检验分级正确

**真实样例（手工，不进仓库）**
用户已有的 iBright 14 张、以及维护者本机保存的原始 TIFF（不在仓库、不写进仓库）。用于确认在真实噪声下不崩、数值量级合理。

**回归**
新增 `tests/quant.mjs` 套件，接进 `tests/run.mjs` 与三引擎 CI；按 AGENTS.md 的约定用真实鼠标事件驱动，不用 `evaluate` 绕过 UI。

- 空白道积分接近 0（无零截断偏置）
- 饱和道 `excludedFrac > 0.02` 且 `quantifiable=false`
- 窄带不被读成宽带
- 16 bit → `ok`；8 bit → `display-8bit`；未知位深不臆断

**真实样例**（维护者本机的一张 iBright 导出 TIFF，2362×1889，8-bit RGB，5 个区域 × 3 道；文件不在仓库）
- 体积 38 – 2388，背景 0.17–0.32，SNR 4.3–58，无异常值

- 一条道的 `excluded_frac = 0.19` 被判为不可定量，正确给出 `(SAT)` 而不进比例

### 6.2 P1–P3 落地记录（2026-11-05）

P0 之后同分支完成 P1、P2、P3；未合并 `main`、未升版本号（仍 0.14.0）。

**改动**
- `js/wbengine.js`：`WB.totalSignal`（染色图取反信号 + 极性判定 + 染色饱和拒绝）、`WB.linearFit` / `WB.linearVerdict`（过原点回归，**非中心化** R²）、`quantify` 新增 `fullLane`（整道积分，无条带剖面可循）。
- `js/wbapp.js`：`S.quant` 设置（`version/method/controlRow/totalImage/dilution`，旧项目无此字段，全部经 `App.quantSettings()` 读取）；`quantLaneSpec` / `quantTotalLaneSpec` / `quantBlock` / `quantData` / `quantLinearity` / `quantDilution`。面板与全部导出都走同一个 `quantData()`，屏幕数字与导出数字不可能分叉。
- `js/wbui.js` + `index.html` + `css/style.css`：`#quantDlg` 面板（归一化方式、内参选择、总蛋白图、线性检验、稀释序列、三条导出）与 `quantCsv` / `quantJson` / `quantMethods`。

**P1 线性检验两模式**
- A 多曝光：同一行的各次曝光（`rowExpo().factor`）对体积做过原点回归；不足 3 个**可用点**（饱和曝光掉出拟合）或几次曝光时长全相同 → 明确说「点数不足」，不下结论。
- B 稀释序列：用户手写上样比例，体积对比例回归。
- 判据：R² ≥ 0.98 且最大残差 ≤ 10% 最强点 → `proportional`，否则 `deviates`；`deviates` 同时进 CSV 警告，措辞是「不要当作倍数变化报告」。
- **边界要讲清**：A 检验的是**检测器**（信号是否随曝光时间线性），不是「信号是否与蛋白量成正比」——后者只有 B 模式的已知上样量能证明。方法段落的措辞按此写。

**P2 总蛋白归一化**
- `totalSignal` 用 `E.detectBright` 判**条带**是否亮：亮条带 = 化学发光帧，直接拒绝（`null`）而不是悄悄取反；暗条带亮膜才按 `1 - pixel` 积分。
- 染色过载判据：`mx > 0.2` 且极值像素数 ≥ max(6, 2e-6·N) → 视为该染色道过载，`clip = mx`，交给 `quantify` 按饱和处理（给下界、不给比值）。
- 总蛋白图必须与要归一化的行**在同一个图片组**，否则 `total-not-in-group`，不给数字。

**P3 重复与方法段落**
- 复用成图已有的 `columns().groups`（第 5 步的条件行）作为重复：`n / mean / SD / CV`；**不**内置检验、不出 p 值。
- `quantMethods` 生成英文方法段落（稿件语言），随归一化方式变化，并声明「No significance test was applied by the software」。

**测试暴露的一个真 bug（已修）**：`quantBlock` 里总蛋白路径写成 `x.specs.map(s => App.quantTotalLaneSpec(s))`——`x.specs` 已经是**道规格**（没有 `.pc`），而 `quantTotalLaneSpec` 要的是**源片段**，于是整道返回 `null`，所有总蛋白体积恒为空。已改为从 `C.src[ri]` 取源片段，并由「合成染色图 → 归一化后必须还原 1:2:…:9」的端到端断言钉住。这类 bug 只有真跑数据才会露头，单看代码很像对的。

**合成验证**（`tests/quant.mjs`，18 项，chromium / firefox / webkit 全过）
- 引擎：振幅序列还原、空白道不虚高、饱和道拒绝、积分宽度跟随条带、位深分级、`fullLane` 宽度、过原点回归的判别力、染色极性/化学发光拒绝。
- 面板与导出（真实 locator 点击）：建议内参、逐行线性结论、`sum` 方式每行归一化后和 = 1、`none` 无比值、弱内参告警（`frac < 0.1`）、条件行 n/mean/SD/CV、**涂一张合成 Ponceau 图后 9 条道的总蛋白体积按 1:2:…:9 还原**、CSV 各分区、JSON、方法段落。

## 7. 明确不做 / 话术边界

- **不**宣称结果「可用于发表」。工具能保证的是参数透明、可复现、线性受检；**是否满足某期刊要求由作者与期刊决定**。
- **不**内置显著性检验与 p 值。
- **不**自动认定内参（名字正则保留为「建议」，正式判定靠用户显式指定）。
- **不**把不同膜、不同曝光拼成一行（既有产品边界，定量不开口子）。
- **不**做条带自动去背景的「美化」类处理——那会让图像不再忠实。
- 8-bit 来源的定量结果在导出中**必须**带降级声明。
