## 0. 一句话

把「定量分析…」从导出菜单里的一个弹窗，改成**成图确定之后一键进入的第三个工作区**：左栏做决定、中间看成图、右栏看数，改任何设置表格与成图上的标注**当场更新**。它不是一个新步骤，五步流程一字不动。

## 1. 为什么不是「第 6 步」

`AGENTS.md` 把五步定成产品边界，理由不是省事，而是**定量不产出图**：五步的每一步都在为成图增加内容，第 5 步之后成图已经完成，再往下走没有「下一阶段」可言。定量是对已完成成图的**另一种读法**。

所以形态是**工作区（workspace）而不是步骤（step）**：

| | 步骤（现有） | 工作区（本设计） |
|---|---|---|
| 菜单 | 五个 `.sec.step`，有编号、有展开/收起 | 不占编号，进入时整页切换（同 `body.gallery-mode` 的做法） |
| 状态 | 一切改动都进撤销历史 | 读成图；只有 `S.quant` 设置进历史 |
| 退出 | 进入下一步 / 回上一步 | `← 返回成图` / `Esc`，回到进入前的那一屏 |
| 数据 | `S` | `S.quant`（已有）+ 模块内的界面状态 |

`body.gallery-mode` 已经证明这套做法在这个代码库里成立（`js/wbextras.js:71` 切换，`css/style.css:585-604` 定义），新工作区照抄同一套机制，叫 `body.quant-mode`。

## 2. 入口与出口

### 2.1 主入口：第 5 步底部的一张卡

第 5 步（名称与导出）展开后，在现有 `.step-next`「导出」按钮**下面**加一张卡：

```
┌──────────────────────────────────────────────────────┐
│ 📊  还要出数？                                        │
│     成图已经定稿。可以在这里量条带体积、按内参或总蛋白  │
│     归一化、看重复的 mean±SD，并导出 CSV 与方法段落。   │
│                              [ 打开定量工作台 → ]     │
└──────────────────────────────────────────────────────┘
```

- 用现成的 `.sec` 卡片样式（`<section class="sec">` 去掉 `.step`），不加编号圆点。
- 只在 `#secNames` 展开且 `lastFig` 已生成时出现——即「确定成图后」。
- 措辞刻意不说「分析」，说「出数」：用户在这一步脑子里想的是「图做好了，数字在哪」。

### 2.2 次入口：导出菜单里的同一项

`导出 ▾` 里的「定量分析…」保留，但**行为改成打开同一个工作区**（现在打开的是 `#quantDlg` 弹窗）。理由：已经用过一次的人肌肉记忆在那儿，砍掉入口等于让他重新找。两个入口一个终点，不存在两套 UI。

### 2.3 出口

| 方式 | 行为 |
|---|---|
| 左上 `← 返回成图` | 回到进入前那一屏（记住 `App.curStep` 与展开状态） |
| `Esc` | 同上。与全应用一致：`Esc` 永远只做「退出当前模态」 |
| 顶栏五步菜单任意一步 | 直接退出工作区并进入该步（不拦） |

退出**不弹确认**：工作台不产生会丢失的东西，`S.quant` 每次改动已经 `commit()`。

### 2.4 进入前的门槛

只有一个：成图存在（`lastFig`）。没有泳道、没有名称、没有内参都不拦——那些是工作台里要解决的问题，不是进不去的理由。

### 3.2 三栏职责（一条硬规则：**同样的信息只出现一次**）

| 栏 | 只放 | 不放 |
|---|---|---|
| 左 · 设置 | 需要**做决定**的：归一化方式及其依赖项、线性结论、导出 | 逐道数值 |
| 中 · 成图 | 成图本身 + 叠层标注 | 任何输入控件 |

## 4. 交互语法（全部复用已有手势）

这是降低学习成本的关键：**不发明新手势**。

| 手势 | 在应用里现在的含义 | 在工作台里的含义 |
|---|---|---|
| 点成图上的条带 | 第 3/5 步：选中该蛋白框 | **同一含义**：选中表格里那一行 |
| 点 `⋯` | 第 3 步：打开该框的区域设置弹层 | **同一含义**：打开该行菜单（稀释序列、换曝光、这一行怎么算的） |
| 拖成图上的 `rowtag` | 调整顺序 | 只允许左右拖动看对齐，不改顺序（工作台不改图） |
| `Esc` | 退出当前模态 | 返回成图 |
| 顶栏教练条 | 「现在该做什么」 | 「① 看线性 ② 选归一化 ③ 导出」，做完一条打勾 |
| 左栏 `.field` / `.inline-label` / `.hint` | 表单 | 完全一样，同样的 330px 宽度、同样的行高 |

**唯一的新东西是右栏的表格**，但它长得像用户已经熟悉的东西：Excel / Prism 里那种「蛋白 × 泳道」的格子，外加每行一个状态标记。

## 5. 左栏详解

### 5.1 ① 归一化

三个单选（不是下拉——四个选项、每个都要一句解释，下拉会把解释藏起来）：

```
① 归一化
  ● 内参蛋白         同一条膜上的一个蛋白，逐道相除
    [ GAPDH ▾ ]      建议值来自名称（GAPDH/ACTIN/TUBULIN…），仅为建议
  ○ 总蛋白           用 Ponceau / 考马斯 / stain-free 图逐道积分
    [ Ponceau.tif ▾ ] 只能选与要归一化的行同一张膜的图
  ○ 各道总和         每一行除以本行各道之和（Degasperi 的总和法）
  ○ 不归一化         只给体积，不给比值
```

- 切换方式后，下面依赖的字段出现/消失（`total` 才出现总蛋白图，`control` 才出现内参选择）。
- 每次改动 `App.setQuant()` → `commit()`，于是**撤销/重做对定量设置同样有效**，与全应用一致。
- 选中 `control` 但没指定行 → 该行自动取 `App.suggestControl()` 的建议值，但**是用户点了才算数**：未点选时显示「未指定（建议 GAPDH）」，比值列显示 `—`，并给 `no-control` 警告。

### 5.2 ② 线性检验

不是「按钮 → 出一个报告」，而是一张**每行一行的清单**，因为结论是**逐行**的：

```
② 线性检验
  GAPDH     ✓ 成正比     R² 0.998
  p-AKT     ⚠ 偏离       R² 0.91 · 最大残差 18%
  AKT       · 点数不足   只有 2 次可用曝光
  稀释序列   [ 展开 ]     逐行填写已知上样比例，做真正的正比检验
```

三种标记与 `linearVerdict()` 一一对应：

| 标记 | 条件 | 中文 | English |
|---|---|---|---|
| ✓ | `proportional` | 成正比 | proportional |
| ⚠ | `deviates` | 偏离 | deviates |
| · | `not enough points` | 点数不足 | not enough points |

点任一行 → 右栏滚到该行并选中。**「稀释序列」是折叠的**（`details.adv`），因为多数人不会填；展开后是每行一个输入框。

### 5.3 ③ 重复与统计

```
③ 重复与统计
  条件来自第 5 步的条件行：Ctrl（1–3）· KD（4–6）
  [ 去第 5 步编辑条件行 ]
```

两种状态：

- 有条件行 → 显示条件摘要，右栏出现统计块。
- 无条件行 → 这一块不显示统计，只给一句话 + 一个按钮（见 §7 的 `no-conditions`）。

### 5.4 ④ 导出

四个按钮，都不是下拉：

```
④ 导出
  [ 方法段落 ]  [ CSV ]  [ JSON ]  [ 复制表格 ]
```

- 「复制表格」是新增的：把当前视图（体积或归一化）复制成 TSV，直接粘进 Excel / Prism。这是研究者实际最高频的动作，比 CSV 少一步。
- 四个按钮的产物内容与现在 `quantCsv` / `quantJson` / `quantMethods` 完全一致——**屏幕上的数、CSV 里的数、方法段落里的数来自同一个 `App.quantData()`**，不可能分叉。

## 6. 右栏详解

### 6.1 表格

```
┌──────────────────────────────────────────────┐
│ 蛋白            1    2    3    4    5    6   │  ← 表头：泳道号（有泳道名则显示名）
├──────────────────────────────────────────────┤
│ GAPDH   ✓     ▇    ▇    ▇    ▇    ▇    ▇    │  ← 行头：名称 + 线性标记
│ p-AKT   ⚠     ▇    ▇    ▇    ▇    ▇    ▇    │
│ AKT     ·     ▇    ▇    ▇    ▇    ▇    ▇    │
└──────────────────────────────────────────────┘
```

- **行头**：蛋白名（与成图上的完全一致，含上下标）+ 线性标记 + 多膜时的膜名小标签。
- **格子**：数值 + 一条按行最大值缩放的迷你条。数值有效数字统一 3 位；极小值用科学计数法（`1.2e-3`）。
- **状态覆盖**：`SAT`（过曝，只给下界）、`—`（该道为空 / 无分母）、`n/q`（不可定量）。
- **两种视图**，右上角切换：
  - `体积`：原始积分体积
  - `归一化`：除以分母后再除以第 1 道 = 相对倍数（0.31 这种）
- 列宽固定（数值 44px + 条 8px），泳道多时横向滚动，行头 `position: sticky; left: 0`。
- 悬停某格 → 成图上对应的条带加深 + 该格浮出 `体积 1240 · 背景 0.021 · 宽 47px · SNR 32`。**只读缓存，不重算。**

### 6.2 选中行详情（表格下方，固定高度 ~240px）

点任意行（或点成图上的条带）→ 下方展开这一行：

```
── p-AKT ───────────────────────────────────  ⚠ 偏离
归一化值（相对第 1 道）
 1.00  0.92  0.88  0.35  0.31  0.29
 ███   ███   ███   ██    █     █
 Ctrl n=3  mean 0.933  SD 0.061  CV 6.6%
 KD   n=3  mean 0.317  SD 0.031  CV 9.8%

线性：跨 4 次曝光，R² 0.912，最大残差 18%（第 3 次）
```

这里放三样表格放不下的东西：条形图、条件统计、线性拟合细节。条形图用 SVG 手画（项目无依赖，不引图表库），复用成图配色。

### 6.3 行菜单 `⋯`

与第 3 步的 `⋯` 同一个 `.popover`（`js/wbui.js:601`），内容三项：

| 项 | 作用 |
|---|---|
| 稀释序列 | 这一行各道的已知上样比例，做 B 模式线性检验 |
| 换曝光 | 从该行的其他曝光里选一张（饱和/线性更好的一张）。**会改成图**，但和在第 3 步改是同一件事，走 `commit()`，可撤销 |
| 这一行怎么算的 | 展开参数：积分宽度、背景模型、饱和排除比例、位深 |

「换曝光」直接解决用户看到 `SAT` 时最自然的下一步动作，而现在的弹窗只会让他退出去第 3 步。

## 7. 成图叠层

叠层用 `BRender.build()` 已经给出的几何，不新增坐标换算：

```js
const f = lastFig;   // { rowBoxes:[{id, columnId, x0, x1, y, h}], laneX, laneW, w, h }
```

| 叠层 | 画什么 | 何时 |
|---|---|---|
| 行描边 | 选中行（`rowBoxes` 里 `id` 匹配）画 1px 蓝框 | 始终有选中行 |
| 格子高亮 | 悬停/选中格 → 该泳道列 `laneX.get(lane)` 到 `laneX.get(lane) + laneW` 乘行高，填 12% 蓝 | 悬停格 |
| 状态标记 | 该行有 `deviates` / 不可定量 → 行右侧一个小圆点 | 始终 |

**刻意不画积分窗。** 积分窗在**源图**坐标系里（`quantify` 采样的 u/v），把它准确放到成图上要穿过 `toImg` → 片段帧 → 成图 pt 三层换算，画错一点就是「图上看着框住了，实际没框住」——比不画更糟。**诚实的做法是给数字不给假框**：悬停格浮出的 `宽 47px` 是真实值，想知道框在哪就回第 3 步看膜的视图（那里坐标是自然的）。

叠层是 `#preview` 上的**绝对定位 SVG 覆盖层**，与第 5 步的 `ov` 同一个做法（`js/wbui.js:1559` 附近），不重建成图。

每条都要有中英双语，走 `L()`。中文在左、英文在右，与代码里 `qWarnText()` 的写法一致。

| code | 触发 | 屏幕上 | English |
|---|---|---|---|

新增（工作台把一些现在「没有」的状态显式化了）：

| code | 触发 | 屏幕上 | English |
|---|---|---|---|
| `no-conditions` | 无条件行 | 成图还没有条件行。第 5 步加一个条件行，就能按重复统计。`[ 去第 5 步 ]` | No condition rows yet. Add one in step 5 to get replicate statistics. |
| `empty-row` | 某行全部道都空 | `<行名>`：这一行没有可量的条带。 | `<row>`: this row has no measurable band. |
| `no-exposures` | 该行只有一张图 | `<行名>`：只有一次曝光，无法做多曝光线性检验。可填稀释序列。 | Only one exposure: no multi-exposure linearity check. A dilution series would work. |
| `all-saturated` | 全部曝光都饱和 | `<行名>`：每一次曝光都过曝，请回第 3 步换更短的曝光。`[ 去第 3 步 ]` | Every exposure is saturated… |

界面文案约定：

- 单位与术语统一：**体积**（volume）、**归一化**（normalised）、**道**（lane）、**重复**（replicate）、**条件**（condition）。
- 永远不说「可用于发表」。方法段落的最后一句话已经声明无显著性检验，工作台里同样不出现 p 值。
- 数字旁边不写「≈」。

## 9. 实时计算的性能模型

实测（demo：2 张膜、6 张图、5 行、9 道）：

| 操作 | 耗时 |
|---|---|
| `App.quantData()` 全量 | **6.2 ms** |
| 全部行的线性检验 | **14.5 ms** |

结论：**每次改动全量重算完全够用**，不需要增量计算。策略：

1. 设置变更 → `requestAnimationFrame` 合并，一帧最多重算一次 `quantData()`。
2. 线性检验贵一倍多，按签名缓存：`行.segs 的 id + row.img + 该行曝光列表` 不变就复用。换曝光、改框才失效。
3. 表格**局部更新**（只改单元格文本与条宽），不重建 DOM——重建会让滚动位置和焦点跳掉，也会让 iOS/WebKit 闪。
4. 悬停不触发任何计算。
5. 真实 2362×1889 图比 demo 大 2.5 倍，最坏估算 15–40 ms/次——仍在「点一下立刻变」的范围内。若某个用户真的卡，第一步是给线性检验上 `requestIdleCallback`（已列在待验证里，Safari 侧无此 API，需 fallback 到 `setTimeout`）。
